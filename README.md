# 胶片核对台（分镜核对 + 离线修复调度）

纯前端本地应用，无需联网、无需构建，直接打开 `index.html` 即可使用，也可在本目录启动静态服务访问。
顶部两个页签分别面向不同工作：

## 1. 胶片分镜条核对台

整理纸质放映胶片片段、拖拽调整放映顺序、统计总时长、筛选颜色偏移并生成试映前破损提醒、导出清单。

## 2. 离线修复调度台（放映员 / 修复师 / 资料管理员）

- **损伤登记**：每卷片段可勾选多项损伤（清洁、齿孔、重接、打磨、补色、放映复检、归档）。
  **每项损伤是一道独立工序**，各带岗位、工时与设备；同一任务的多道工序按固定工序顺序
  （清洁→齿孔→重接→打磨→补色→复检→归档）依次完成，表单实时汇总总工时以及涉及的全部岗位/设备。
  可设优先级、备注与跨任务前置依赖（前置任务的末工序完成后，本任务首工序才能开工）。
- **自动排程**：以**工序步骤**为粒度做拓扑排序，按优先级、早晚班工时容量、人员岗位与
  **每道工序的设备**占用求最早可行工作日；同一人员、同一设备绝不重叠——非主损伤的岗位与设备同样参与，
  不会漏排（例：同时勾选清洁+放映复检，清洁台与放映机都会被占用）。人员与设备均可增删。
- **手动改派**：甘特图按人员泳道（附设备占用行）展示每个工序色块，拖动单道工序改派即"钉住"该步骤，
  松手立即标出人员重叠、设备重叠、工序/依赖倒置、岗位不符、缺资源等冲突，并脉冲红框提示。
- **保存门禁**：存在任何冲突（含依赖成环、任一道工序未能排程）时保存按钮禁用，冲突版本**不写入**
  localStorage，刷新即回到上次干净版本。
- **总工期与风险**：任何改动（含修改损伤组合）后全部工序自动重排，重算预计完工天数与风险指数
  （损伤基础风险 + 硬冲突×25 + 其他冲突×8 + 工期×2），并列出风险构成。
- **批量事务**：多选任务批量改优先级或损伤（追加 / 替换），先弹窗预览工期、风险、冲突工序数及
  逐任务改动，确认后作为一次事务提交（受影响任务的工序整体重排，未动任务的手动钉住保留）；
  预检或提交中任一步失败全部回退、零写入。
- **撤销 / 刷新保留**：支持撤销上一次批量提交（含各工序原排程，撤销栈持久化）；
  排程、资源、开工日期、撤销栈刷新后均保留。
- **班表导出**：一键导出带 BOM 的 UTF-8 CSV（Excel 中文不乱码），按工序逐行、跨工作日按天展开，
  含日期/星期/班次时段/人员/岗位/卷/片段/工序/工时/设备/前置工序；未排程与冲突工序单列警示段。

数据保存在浏览器 localStorage（键：`zfl17-film-strip-desk`、`zfl17-film-repair-desk-v2`）。

### 旧版本数据迁移与损坏防护

调度台启动时按 **有效 v2 → 可迁移的旧版（`...-v1` / `...-v0`）→ 种子数据** 的顺序加载：

- v1 旧数据（任务级单一排程）会自动迁移到步骤模型：胶片卷、人员、设备、任务与依赖保留，
  多损伤任务展开为多道工序，旧的任务级排程作废后按当前资源自动重排；迁移结果立即写入统一键 v2，
  刷新不丢，并在页面顶部提示迁移数量。
- 无法识别的字段按可用默认值处理：未知岗位→修复师、未知班次→早班、未知优先级→中、
  坏日期→今天、缺 id 自动补号、重复 id 重新分配、幽灵/自依赖清除、未知损伤的坏条目跳过、
  指向已删除人员/卷的排程与引用回收、撤销栈只保留合法快照。
- 损坏数据不会覆盖现有状态：v2 损坏则回退 v1，二者皆坏才退回种子，且页面顶部给出说明；
  结构有效但带成环等排程冲突的存档会完整保留并提示，由用户处理后再保存。

## 端到端验证（真实 Chromium）

```bash
cd .e2e
npm i
npx playwright install chromium
# 在仓库根目录启动静态服务：python3 -m http.server 8717
npx playwright test
```

`.e2e/repair.spec.js` 共 17 个串行用例，覆盖：原核对台回归、多卷登记、混合损伤多步骤入排
（清洁+复检分别占清洁台/管理员与放映机/放映员）、共享非主设备同日冲突、修改损伤后工序重排、
依赖成环门禁、人员/设备拖拽冲突、全自动重排、批量预览/失败回退/成功提交/撤销、追加损伤、
刷新保留、干净与冲突两版 CSV 导出、无空壳入口校验；全程断言页面无 JS 报错。
